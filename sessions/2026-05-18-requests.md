# 2026-05-18 — requests from local-web

## Request 1 — URL prefix support via env var (12-factor)

**Status:** spec / partial — `--url-prefix` CLI flag exists; env var equivalent does not

**Ask.** glow-web should accept the URL-mount prefix via 12-factor
config sources (CLI > env > config-file-if-any), not via request
header.

**Current state.** glow-web's `web` subcommand already has the CLI flag:

```
glow-web web <root> --url-prefix /wt/main
```

(from `cmd/glow-web/*.go`: `prefix := fs.String("url-prefix", "", …)`)

Confirm this is what's needed. The local-web supervisor
(`local-mux`) currently spawns glow-web without `--url-prefix`,
which means glow-web generates links relative to its own root `/`,
not relative to the Caddy-stripped prefix `/wt/<wt>/`.

**Asked additions.**

1. **Env-var equivalent**, e.g. `GLOW_WEB_URL_PREFIX` honored when
   the CLI flag is absent. Standard 12-factor precedence: CLI
   overrides env. This lets the supervisor set the prefix via env
   in the launchd plist (consistent with how it might evolve to
   pass other tunables) without having to thread it through every
   `subprocess.Popen` args list.
2. **Explicit refusal to honor an `X-Forwarded-Prefix` header** (or
   document if already so). Reason: headers are forge-able by
   clients; treating them as authoritative for routing/prefix
   semantics opens path-confusion attacks. A reverse proxy *can*
   set them, but glow-web shouldn't trust them as the source of
   truth — startup config is.

**Why now.** local-web v0.6 ships with Caddy `handle_path
/wt/<default>/* { reverse_proxy 127.0.0.1:<port> }`, which strips
the prefix before glow-web sees the request. glow-web then
generates relative links assuming root `/`, breaking absolute-link
construction in clients that resolve from the original URL.

The supervisor will start passing `--url-prefix /wt/<wt>` when
spawning, but the env-var route lets ad-hoc launches (developer
tmux pane, manual `glow-web web . --url-prefix=…`) reuse the same
mechanism without remembering flag names.

**Cross-link:** `~/dev-llm/claude-collab/local-web/specs/url-stability.md`
and `~/dev-llm/claude-collab/local-web/STATUS.md` (open follow-up
"glow-web `-url-prefix` wiring") track this from the local-web side.

**Suggested implementation sketch.**

```go
prefix := fs.String("url-prefix", "", `…`)
// after fs.Parse:
if *prefix == "" {
    if env := os.Getenv("GLOW_WEB_URL_PREFIX"); env != "" {
        *prefix = env
    }
}
```

Document the precedence in `--help` and in `specs/spec.md`. Add a
test asserting CLI wins over env.
